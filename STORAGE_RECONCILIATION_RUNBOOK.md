# Storage reconciliation runbook

Status: **OPEN** because the current filesystem contains understood classes of
unregistered legacy/generated bytes that still require an owner-reviewed decision.

Run the host-native read-only report on Windows with:

```powershell
powershell -File scripts/Invoke-StorageReconciliation.ps1 -OutputPath build/d0-storage-reconciliation.json
```

The portable application command is `python scripts/reconcile_storage.py`; it is
suited to a Linux staging host where PostgreSQL and storage are directly accessible.
Both modes are read-only. They compare PostgreSQL artifact metadata with filesystem
bytes, including missing and orphan files, duplicate keys, checksum/size mismatches,
availability drift, temporary files, abandoned uploads, legacy `job.json`, unsafe
paths, and cross-owner metadata. Output ordering is deterministic.
