# Offline Pickleball court benchmark v1

This is the Phase 1 benchmark foundation. It evaluates the **unchanged automatic detector** against independently supplied labels. It does not train, alter detector thresholds, verify a production calibration, load workflow/database services or register artifacts. No production module imports these scripts.

## Current data and pilot boundary

`manifest.v1.json` intentionally contains **zero frames**. There are currently **zero reviewed real frames in this benchmark format**. The preceding audit found 179 local sampled JPEGs but only 24 unique SHA-256 contents; those include repeated/synthetic material and do not constitute a representative dataset. No existing auto corners or user confirmations were converted to ground truth. Synthetic images generated by the focused tests are algorithm checks only, excluded from real-data counts.

Next collect the audit's proposed 120 distinct real frames from about 20 independent recording/camera groups across at least eight venues, including at least 30 partial/ambiguous/negative cases. Label visible landmarks and line runs independently, with a second reviewer; split whole groups (approximately 80 development / 40 evaluation). Include known high-confidence failures, varied lighting/paint, far-half occlusion, cropped courts and competing court markings. Usage eligibility and source retention must be established before copying real media. Model training and runtime integration remain out of scope.

## Run

From the repository root with its Python 3.12 dependencies installed:

```powershell
python -m scripts.benchmark_court_vision --manifest calibration/court_vision/manifest.v1.json --image-root . --output-dir data/output/court-vision-pilot-001
```

The output directory must be new: reruns use a different directory. Prefer a repository-managed offline location as above. Input paths resolve beneath the explicitly supplied image root; escaping paths/symlinks are refused. Missing, corrupt, checksum-mismatched or dimension-mismatched inputs become reported abstentions without detector replay. Invalid annotation structure fails the run, rather than silently dropping labels.

Outputs are `results.json` and `REPORT.md`. Temporary calibration/overlay artifacts created by the detector are isolated in an automatically cleaned child directory of the output directory. Existing analysis artifacts are never changed. The report shows outcome counts, recording/venue groups, frame-level corner/line errors and abstention/contradiction reasons. JSON also records splits, data kinds, source-code hashes, dependency versions, manifest hash and evaluation policy. Empty input explicitly records zero reviewed real examples, no real-world accuracy conclusion, and unevaluated prototype correctness/coverage gates in both outputs.

Replay uses one image per detector call for attributable frame errors. It does **not** reproduce production best-of-video selection or establish temporal stability. The committed defaults are read from `Settings.model_fields`, without instantiating environment-backed settings: minimum confidence 0.72, low confidence 0.25, polygon area 1000 px², numerical tolerance 1e-6, transition depth 8 ft and top-down width 1000 px at implementation time. Actual options are recorded in every result. No flags override these defaults.

Stable sorting, canonical JSON and omission of timestamps, temporary paths and duration measurements make outputs byte-repeatable for identical labels/images, code and dependency versions. Cross-platform floating point/codec equivalence is not promised. Reports do not claim latency, temporal reliability or population accuracy.

## Annotation contract

The executable authority is `scripts/court_vision_annotations.py`; `annotation.schema.json` is the generated structural JSON Schema. Runtime validators additionally enforce visibility/coordinate consistency, bounds, semantic edge choices and review rules. Start each record from `frame-template.v1.json`, replace its placeholder metadata, and append it to the manifest's `frames` list. The template is draft metadata, not a labeled example.

Manifest versions are fixed: `court-vision-annotations-v1`, `pickleball-court-v1`, and `outside-perimeter-nvz-away-service-center-v1`. Unexpected fields are rejected. Each frame describes **one selected target court**, not a training export of every court in view. For unresolved multiple-court identity, use `partial_or_ambiguous` and unresolved orientation. Multi-instance model training labels are deferred.

Required provenance includes image SHA-256, source reference, usage/retention notes, recording/venue/court/camera/shot IDs, split, real/synthetic kind, original decoded dimensions, one-based frame number and timestamp. Source video hash is nullable when unavailable; record that limitation in the source reference. Use globally stable group IDs, not local names such as `camera-1` repeated across unrelated venues. Original decoded pixels are required; do not label resized browser coordinates. Phase 1 has no crop/resize/rotation exporter; normalize the image deliberately before annotation if necessary and retain its derivation in source_reference. Set timestamp to `(frame_number-1)/fps` only where source timing justifies that approximation.

Every frame requires all 12 keys, including unavailable ones. Near/far is camera-relative and left/right follows the selected near-end convention, independent of team identity:

| Key | Coordinate in feet |
| --- | --- |
| near_left | 0, 0 |
| near_right | 20, 0 |
| far_right | 20, 44 |
| far_left | 0, 44 |
| near_nvz_left | 0, 15 |
| near_nvz_right | 20, 15 |
| far_nvz_left | 0, 29 |
| far_nvz_right | 20, 29 |
| near_baseline_center | 10, 0 |
| near_nvz_center | 10, 15 |
| far_nvz_center | 10, 29 |
| far_baseline_center | 10, 44 |

A visible point is `{"visibility":"visible","xy":[123.5,456.0],"uncertainty_px":1.5}`. `occluded_localizable` also requires coordinates/uncertainty, but those points **never contribute to observed metric support**. `unknown` and `outside_frame` require null/absent coordinates and uncertainty; do not hallucinate offscreen points. Every localized coordinate must be finite and inside the image. Unknown entries cannot be omitted entirely.

Every frame also requires eight line keys: `near_baseline`, `far_baseline`, `left_sideline`, `right_sideline`, `near_nvz`, `far_nvz`, `near_center_service`, `far_center_service`. Outer lines use `outside_perimeter`, NVZ lines use `away_from_net` (y=15/29), and service lines use `stripe_center`. Service lines end at their NVZ boundary. Net tape, posts, virtual net-floor line and derived transition boundaries are excluded.

Example of two separately observed runs of the same NVZ reference edge:

```json
{
  "reference": "away_from_net",
  "visible_runs": [
    {"points": [[120, 250], [210, 260]]},
    {"points": [[300, 270], [420, 285]]}
  ],
  "uncertainty_px": 2,
  "paint_width_px": 4,
  "unobserved_reason": "occluded"
}
```

Each run is an uninterrupted polyline with at least two distinct consecutive points. Split at occlusion; never join across a player. Coordinates specify the reference edge/center, not whichever paint edge is easiest to see. Uncertainty applies to that reference. Paint width is descriptive and never widens acceptance tolerance. Unobserved spans are represented by gaps between visible runs plus `occluded`, `outside_frame`, `unknown` or `mixed`; an entirely missing line has an empty list, not a fake zero-length line. Use `none` only when no unobserved portion remains. Overlapping duplicate runs are not additional evidence; union coverage prevents them inflating coverage, but annotators should not duplicate runs.

`review_status=reviewed` requires a reviewer distinct from the annotator. Labels should be made from source images without showing detector overlays, then adjudicated; set unresolved labels unknown. `draft` and unresolved orientation abstain. Record conditions in tags/reasons and choose `full_geometry_supported`, `partial_or_ambiguous`, or `no_target_court`. No-target frames require all keypoints unknown and no visible target lines. Synthetic review names in tests denote analytical fixtures, never actual human review.

## Metrics and outcomes

The evaluator receives proposed ordered corners only, **not detector confidence**. It independently constructs a homography from those corners to the fixed template. Annotation coordinates are never fitting inputs. It compares projections of named template points with visible human point labels, so a low fitting residual cannot self-certify geometry.

- Corner, interior and all-landmark image errors: count, mean, median, p95 and maximum Euclidean pixels; p95 normalized by image diagonal. Per-keypoint errors are retained. Missing observations produce null metrics, not zero error.
- Court-coordinate error: p95 Euclidean feet error when independently labeled visible pixels are mapped through the proposal's inverse transform. This is a geometry diagnostic, not athlete measurement accuracy.
- Per-line alignment: arc-length-weighted mean/p95/max distance of observed reference-line samples to the **finite** corresponding projected template segment. Uniform midpoint samples are at most 2 px apart; finite endpoints prevent infinite-line extensions from hiding misalignment. p95 diagonal fraction, visible length, support fraction and union projected-span coverage are reported. Only labeled visible runs are scored; unobserved paint contributes nothing. This is a label-based benchmark, not an automatic image-line detector.

Experimental offline policy v1 uses a 0.5% image-diagonal point/line tolerance, 0.5 ft p95 court-coordinate limit, 30% projected coverage and 70% supported visible length per required baseline/sideline/NVZ line. These are evaluation policy constants, not production thresholds or empirically validated guarantees. Acceptance also requires reviewed full-geometry labels, known orientation, all four observed corners and at least two observed interior landmarks. This conservative foundation is narrower than the later six-distributed-keypoint model plan. Annotation uncertainty cannot manufacture acceptance: high uncertainty or measurements exceeding tolerance but within label uncertainty abstain.

`accept`: proposal has sufficient independent label support and passes all implemented checks. `incorrect`: reviewed evidence contradicts the proposal, geometry is invalid, or a proposal appears on a reviewed no-target frame. `abstain`: no proposal, invalid input artifact, unreviewed/unresolved/incomplete evidence, or uncertainty prevents assessment. An abstention is not counted as correct. Contradictions take precedence over incomplete coverage when orientation and labels are assessable. `accept` never updates or denotes Court4's verified state.

Detector `detected`/`low_confidence`/`failed`, score and proposed corners are recorded separately. Even a low-confidence or failed candidate with returned corners receives geometric evaluation; this keeps geometric quality distinct from the baseline detector's decision. A high-confidence wrong rectangle is still incorrect. Outcome totals are proposal-evaluation totals, **not production acceptance precision**. All frames, including decode failures, remain in group counts.

## Leakage and tests

Reports group by recording, venue, split and real/synthetic kind. Cross-split sharing of recording, venue, court, camera setup, source video hash or image hash generates explicit warnings and frame IDs. These are diagnostics, not an automatic split repair. Exact duplicate images count once in `unique_images`, but frame outcome totals retain every supplied row. Near-duplicate/visual deduplication and independence require human dataset curation; a zero-warning manifest is not proof of no leakage. Do not claim holdout accuracy until warnings and unknown provenance are resolved.

Run the isolated suite without the repository's unrelated global database fixtures:

```powershell
python -m pytest --confcutdir=tests/offline_court_vision tests/offline_court_vision -q
python -m ruff check scripts/court_vision_annotations.py scripts/court_vision_metrics.py scripts/benchmark_court_vision.py tests/offline_court_vision
python -m mypy --follow-imports=silent scripts/court_vision_annotations.py scripts/court_vision_metrics.py scripts/benchmark_court_vision.py
```

No original tests or fixtures are changed. Tests cover schema errors, occlusion/missingness, exact geometry and known offsets, internal-line disagreement despite correct corners, insufficient/duplicated line runs, no-target inputs, existing-detector correct/background proposals, artifact integrity, split leakage, byte-deterministic JSON/Markdown, and CLI empty/overwrite behavior.

Automatic pixel-line extraction, temporal camera registration/consensus, overlays for annotators, training exports, multi-instance labels and model training are not implemented by this smallest foundation. They must not be inferred from a passing per-frame benchmark. The foundation is ready to collect and assess a labeled dataset pilot; geometry accuracy is still unmeasured on real labeled data.
